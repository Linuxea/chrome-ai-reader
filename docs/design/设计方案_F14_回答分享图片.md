# 设计方案：回答生成分享图片（F14）

> 输入：用户口头需求（本会话对话），无独立意图文档，需求编号由本方案提炼
> 代码基线：main 分支工作区（2026-11-09）
> 已确认决策：卡片内容 = 问题 + 回答 + 来源；配色 = 固定浅色 + 主题点缀色；动作 = 仅下载 + 复制（不做系统分享）

## 1. 结论摘要

零新依赖实现"AI 回答 → 分享卡片 PNG"：复用 `renderMarkdown()` 渲染回答正文，构建自包含样式的离屏卡片 DOM，经 SVG `foreignObject` → `Image` → `canvas` 栅格化为 2x PNG。UI 上在现有 AI 回答操作按钮行（`ui/tts-buttons.ts`）加一个分享按钮，弹出预览 modal 提供"下载 / 复制图片"两个动作。改动集中在 side panel，共 3 个新文件 + 6 处修改，另需 manifest 增加 `clipboardWrite` 权限。最大风险是剪贴板写图片对权限的依赖（已通过 manifest 声明解决）与超长回答的 canvas 尺寸上限（先缩放后截断兜底）。

## 4. 设计方案

### 4.1 核心管线（services/share-image.ts 新增）

```
buildShareCard(data) → 卡片 DOM（挂 body 下、left:-9999px 测量实际高度）
  ↓ XMLSerializer
<svg xmlns width height><foreignObject>卡片HTML(含内联<style>)</foreignObject></svg>
  ↓ Blob URL → Image → canvas.drawImage（scale=2，输出 1440px 宽）
PNG Blob → downloadFile() / navigator.clipboard.write(ClipboardItem)
```

- 卡片 DOM 根元素需带 `xmlns="http://www.w3.org/1999/xhtml"`，序列化才合法
- 全部样式作为 `<style>` 块内联在卡片根内（SVG 自包含硬性要求）；字体走系统栈；无 `url()` 引用
- 测量后立即从 DOM 移除卡片节点
- 选择此方案而非 html2canvas：项目依赖克制 + Chrome-only 目标下原生 foreignObject 像素级可靠且零体积

### 4.2 卡片规格（ui/share-card.ts 新增）

宽 720 CSS px，输出 2x（1440px PNG）：

```
┌────────────────────────────────┐
│ ▔▔▔ 顶边条（accent，4px）        │
│ 🍐 小梨子阅读助手     2026-11-09 │  头部：应用名 + 日期
│ 来自《页面标题》                  │  来源行（E-04：空则隐藏）
├────────────────────────────────┤
│ Q 用户的问题（浅灰底圆角块）       │  E-05：无前驱气泡则隐藏
│                                │
│ 回答正文（renderMarkdown 输出）   │  代码块/表格/列表/引用全支持
│ …                              │
├────────────────────────────────┤
│ 由 小梨子阅读助手 生成            │  水印
└────────────────────────────────┘
```

- `buildShareCard({ question?, pageTitle?, date, accent, markdown })` → `{ el, height }`，纯 DOM 构建（jsdom 可单测）
- 问题来源：点击的 AI 气泡向前找最近的 `.user-msg-group .message-user`，取 `dataset.rawDisplay || dataset.rawText`（引用原文与图片不进卡片，E-08）
- 引用 `[#N]` 保持纯文本（不跑 `linkifyCitations`）
- E-01 截断逻辑放本模块：传入 markdown 先按段落累积，超过软上限（约 12000 字符）即停并标记截断；构建后再按实测高度二次校验（>16000px 缩放到 560 宽重建，仍超则依赖字符截断兜底），截断时追加脚注 `share.truncated`

### 4.3 接口 / 交互（features/share-image.ts 新增）

- **按钮**（`ui/tts-buttons.ts` 修改）：在下载语音按钮后追加 `share-image-btn`（图片图标 SVG），无行为回调（ui 层不接线，遵守分层）；`shared/css-selectors.ts` 加 `SHARE_IMAGE_BTN: '.share-image-btn'`
- **wiring**：feature 初始化 `initShareImage({ chatArea })`，在 chatArea 上事件委托监听 `click`，命中 `CSS.SHARE_IMAGE_BTN` 时向上找 `.message-ai` 收集数据（markdown 源 E-07、前驱问题、pageTitle、accent）→ 生成 → 开 modal；E-06：气泡处于流式生成中（无最终态标记）直接 return
- **modal**：feature 内动态创建（参照 `ui/podcast/ui.ts createPodcastCard` 的动态构建风格，index.html 仅挂 css 链接）；结构 = 遮罩 + 对话框（标题、可滚动预览区放 `<img>`、按钮行：下载 / 复制图片 / 关闭）；Escape 与遮罩点击关闭；`.share-modal.hidden` 显式定义（坑）
- **复制**：`navigator.clipboard.write([new ClipboardItem({ 'image/png': blob })])`，成功 toast + 按钮文案瞬时变化（参照复制按钮 1.5s 反馈模式 `tts-buttons.ts:36-47`）；E-03 失败 toast
- **下载**：文件名 `小梨子_日期_页面标题前30字.png`（`sanitizeFilename` + `formatDateOnly`）

### 4.4 一致性与并发

无服务端、无持久化状态：生成是纯前端一次性动作，无事务/幂等诉求。并发防护仅需：生成中按钮防重入（`data-generating` 标记）；modal 单例（已开则复用）。

### 4.5 权限

`public/manifest.json` permissions 追加 `"clipboardWrite"`（`navigator.clipboard.write` 写图片需要；现有 `writeText` 未声明也能跑，但 ClipboardItem 路径建议声明）。发布时用户会看到一次"请求新权限"提示。

### 4.6 配置与开关

无新增设置项（V1 无开关，卡片配色策略固定）。

### 4.7 兼容性与发布

- 仅新增文件 + 追加按钮/权限，无现有行为变更；回滚 = revert 提交，无数据迁移
- `clipboardWrite` 为新增权限：商店更新时已安装用户会收到权限确认，属预期
- manifest 改动后需重载扩展验证

## 8. 风险与待确认

### 8.1 风险
- **foreignObject 栅格化**：Chrome 下成熟（html-to-image 等库同原理），但 emoji / 复杂表格渲染需真机目检（AC 手动项）
- **剪贴板焦点**：`clipboard.write` 要求文档焦点，modal 按钮点击天然满足；仍有失败路径 toast 兜底（E-03）
- **新增权限的发布提示**：`clipboardWrite` 触发已安装用户的权限确认弹窗，需在更新说明中预告

### 8.2 待确认问题
| 编号 | 问题 | 来源 | 当前假设 | 假设不成立的影响 |
|---|---|---|---|---|
| D-01 | 卡片宽 720px / 2x 输出是否合适（用户未明确答复） | 对话遗留微决策 | 720/2x（微信内清晰） | 改常量即可，成本极低 |
| D-02 | 文件名是否要含页面标题（含中文文件名在部分系统的问题） | 设计新发现 | 含（与 md 导出一致） | 改文件名模板一行 |

## 9. 建议（不在本次范围内）
- 系统分享（`navigator.canShare({files})`）：用户已选不做，但接口留 `shareImage` 服务层函数即可未来零成本追加
- 用户消息内 data: 图片进卡片：V1 明确排除（E-08），后续可在 `buildShareCard` 加图区
- 分享卡片多模板 / 暗色卡片：当前固定浅色，模板化后可扩展
