## Build & Run

```bash
npm run dev    # vite build --watch + watch-iife for content/background (development)
npm run build  # vite build && node build-extension.js (production)
npm run build:win  # build with DIST_DIR=/mnt/d/chrome/chrome-ai-reader (fixed Windows output dir)
npm run test   # vitest run (959 tests across 85 files; proxy test files need `ws` installed — see Testing)
npm run test:watch  # vitest (watch mode)
npm run test:coverage  # vitest run --coverage
npm run lint   # eslint (JS + TS via typescript-eslint) && lint:deps
npm run lint:deps  # dependency-cruiser: layer rules + no import cycles (.dependency-cruiser.cjs)
npm run format # prettier --write 'src/**/*.js' 'proxy/**/*.js' — JS only; the TS files that make up most of src/ are NOT covered
npx tsc --noEmit  # TypeScript type check (strict:true)
```

**`npm run dev` watches Vite + IIFE builds** via `concurrently`. All source changes (side panel, options, content script, background) are rebuilt on save. The IIFE watcher and the production build share `scripts/iife-config.js` (entries + esbuild plugin); Vite's `emptyOutDir` is off in watch mode, because Vite empties `dist/` on every watch rebuild and would delete `content.js` / `background.js`.

## Build Architecture (non-obvious)

Two-phase build — Chrome cannot use ES modules for content scripts or service workers:

1. **Vite** (`vite.config.js`) — bundles `src/panel/index.html` and `src/options/index.html` as entry points. Output: `dist/` with chunked JS in `dist/assets/`. Native TypeScript + React + Tailwind v4 (`@vitejs/plugin-react`, `@tailwindcss/vite`).
2. **Rollup IIFE** (`build-extension.js`) — bundles `src/content/index.ts` → `dist/content.js` and `src/background/service-worker.ts` → `dist/background.js` as self-contained IIFE scripts. Uses `rollup-plugin-esbuild` for TypeScript.
3. **Static copy** — `public/` copied verbatim to `dist/` (manifest, icons).

Load the **`dist/`** directory in `chrome://extensions/`, not the project root. The output dir is overridable via the `DIST_DIR` env var (read by both `vite.config.js` and `scripts/iife-config.js`): `npm run build:win` builds to `/mnt/d/chrome/chrome-ai-reader` (Windows `D:\chrome\chrome-ai-reader`), so the unpacked extension keeps working when WSL is shut down.

## TypeScript

- **strict: true** — all `.ts` files are strict-mode TypeScript
- `tsconfig.json` — `noEmit: true`, `allowJs: true` (JS/TS coexist)
- Only `src/shared/i18n.js` and `src/shared/types.js` remain as JS (JSDoc typedefs for legacy consumers; TS types are in `types.ts`)
- Type definitions: `src/shared/types.ts` (TabState, ChatMessage, ToolCall)
- Error handling: `src/shared/result.ts` (Result<T,E>, ok(), err())
- `ChatMessage.role` includes `'tool'` + optional `tool_calls`/`tool_call_id` fields — used by agent mode (F11, see Key Gotchas)

## Source Layout (`src/`)

The side panel is a **React 19 + zustand + Tailwind v4** app in `src/panel/` (rewritten 2026-11 from a hand-rolled DOM panel — migration story in `docs/design/react-panel-migration.md`). Layering is **enforced** by dependency-cruiser (`npm run lint:deps`): violations and import cycles fail the build. Type-only imports count too.

| Layer | Directory | Depends on |
|-------|-----------|------------|
| Shared | `src/shared/` | nothing (pure data + helpers; markdown sanitize pipeline lives here) |
| Platform | `src/platform/` | shared (typed wrappers over `chrome.*`) |
| State core | `src/panel/state.ts` | shared + platform — framework-free TabState core (persistence, per-tab registry) |
| lib | `src/panel/lib/` | state + platform + shared — controllers (send/stream/tts/quiz/podcast), ported services (history-ops, agent-tools, page/pdf extractor, screenshot, share) |
| stores | `src/panel/stores/` | state + lib — zustand stores (tabs/composer/stream/ui/suggest/tts/quiz/podcast/annotation) |
| hooks | `src/panel/hooks/` | stores + lib — auto-resize, stick-to-bottom, throttled text |
| components | `src/panel/components/` | everything below (chat / composer / panels / layout; `components/ui/` = shadcn primitives are leaves) |
| entry | `src/panel/main.tsx` → `App.tsx` | composition root — mounts React, wires global listeners + controller liftoff |

**The state-core + version-counter pattern** (`panel/stores/tabs-store.ts`): `panel/state.ts` is the framework-free core (per-tab TabState map, 250ms-debounced persistence with immediate message-boundary flushes, quota fallback, never restores in-flight flags). React reactivity comes from a zustand wrapper that bumps a `version` counter on every mutation; PURE lib functions (history-ops) mutate TabState objects in place — components subscribe to `version` via `useActiveTabState()`. Never add notification-by-mutation; always bump.

**Theme tokens**: `shared/themes.css` is the single color source (3 themes × light/dark, `data-theme-name` + `data-theme` on `<html>`, pre-paint via `public/theme-boot.js`). `panel/styles.css` maps them onto Tailwind's semantic scale via `@theme inline` (`bg-background`/`text-primary`/…). Never add `--radius-*: var(--radius-*)` — self-referential; the names already align.

**Window-global audio resources** (TTS + podcast): neither stops on tab switch. Takeover wiring lives in `panel/lib/audio-resource.ts` (registration callbacks, no import cycle). TTS playback state derives from the player's notifications into `stores/tts-store.ts` — per-message buttons and the global indicator read it; there are no DOM anchors to detach/reattach.

**Platform layer (`src/platform/`)** — single seam for all `chrome.*` access:
- `ports.ts` — typed `openXxxPort()` helpers over `PORT_NAMES` (defined in `shared/protocol.ts`, the single source of truth for port names — also usable from the SW / content script)
- `settings.ts` — **the** settings API: `readSettings(keys)` / `writeSettings` / `removeSettings` / `onSettingsChange` with typed keys (`Settings`) and defaults (`SETTING_DEFAULTS`). Secrets (`SECRET_KEYS`: `apiKey`, `ttsAccessKey`) live in `storage.local` (never synced), everything else in `storage.sync`; callers never pick an area. `migrateSecretsToLocal()` runs at SW startup
- `storage.ts` — `getSync/setSync/onSyncChange` (low-level; prefer `settings.ts` for settings)
- `tabs.ts` — `getActiveTab/onTabActivated/onTabRemoved`
- `messaging.ts` — `sendMessage/onMessage/openOptionsPage`

**Key lib modules:**
- `lib/send.ts` — message assembly + the single `submit(intent)` pipeline (send button, quick actions, quick commands); retry/edit re-send from history DATA (no DOM rescue)
- `lib/stream-controller.ts` — ai-chat port protocol, idempotent `finalize()` for every end-of-stream path, agent tool loop, abort registry
- `lib/page-extractor.ts` — extraction entry point (notifier injectable via `setExtractingNotifier`)
- `lib/history-ops.ts` — centralized conversation history operations (append/rollback/truncate/branches)
- `lib/chat-save.ts` — IndexedDB chat persistence; DisplayMessage derives from history data

**Shared protocol (`src/shared/protocol.ts`)** — single source of truth for Port wire contracts (`StreamMessage`, `AIChatRequest`, `TTSMessage`, etc.). Pair with `PORT_NAMES`.

**Other entry points:**
- `src/content/index.ts` — content script (IIFE-bundled)
- `src/content/annotation/` — annotation split into focused modules (chunk-collector, quote-wrapper, bubble-ui, orchestrator, styles); `content/annotation.ts` is a barrel re-export
- `src/background/service-worker.ts` — background worker (IIFE-bundled)
- `src/options/index.ts` — settings page (bundled by Vite, split into sections/)

## Events

There is **no event bus** — the legacy `events.ts` carried HTMLElement payloads and died with the rewrite. Cross-cutting reactions go through: zustand stores (UI reacts to state), `subscribe` on the state core (`tabSwitched` / `isGenerating` / `pageInvalidated`, bridged into tabs-store), or registration callbacks (`lib/audio-resource.ts`).

## Chrome Extension Messaging

- **Streaming** (AI chat, TTS, suggest questions): `chrome.runtime.connect` with named ports (`PORT_NAMES` in `shared/protocol.ts`: `ai-chat`, `tts`, `suggest-questions`, `podcast-*`, `annotation`, `translate`, …). The worker dispatches ports and one-shot messages through `background/sw-router.ts` (`registerPort` / `registerMessage` with an audience — `'extension'` pages or `'content'` scripts — checked against the sender; foreign senders are refused). Prefer `src/platform/ports.ts` openers + `src/shared/protocol.ts` types over raw `chrome.runtime.connect`.
- **One-shot** (page extract, selection relay, model list): `chrome.tabs.sendMessage` / `chrome.runtime.sendMessage`. Prefer `src/platform/messaging.ts` wrappers.
- **Config sync**: prefer `platform/settings.ts` `onSettingsChange` (or `platform/storage.ts` `onSyncChange(key, cb)`) over raw `chrome.storage.onChanged` listeners. Changes apply live without reload.

## API Path Convention

`apiBase` does **not** include `/v1`. Endpoints are `{apiBase}/chat/completions` and `{apiBase}/models`.

## i18n

Strings in `src/shared/i18n.js` keyed by dot-notation. DOM auto-translates via `data-i18n` / `data-i18n-html` / `data-i18n-placeholder` / `data-i18n-title` attributes.

## LLM Prompts

All LLM prompts live in `src/shared/prompts.ts` — **not** `i18n.js`. Prompts are semantically distinct from UI strings (they never bind to `data-i18n`) and `i18n.js` is unsafe to import from the service worker (it touches `document`). `prompts.ts` is pure data + a pure `getPrompt(key, lang?, params?)` getter, importable from both the SW (`sw-annotation.ts`) and the side panel. Keys are typed (`PromptKey`); zh is complete, en is partial (podcast is zh-only because its TTS voices are Chinese). Placeholders are substituted in ONE pass with a replacer function, so values (page text) are inserted verbatim — `$&` is not expanded and a `{placeholder}` inside a value is not re-expanded; unknown placeholders and JSON braces stay as-is. The annotation chunk labels are language-neutral `[#N]` (`content/annotation/chunk-collector.ts`), referenced by `annotation.user` in both languages. Side-panel callers pass `getCurrentLang()` from `i18n.js`; the SW reads `language` from `chrome.storage.sync` and normalizes to `'zh'|'en'`. Built-in quick-action prompts follow the UI language (zh + en both defined).

## Key Gotchas

- **No inline `<script>` in extension pages**: MV3's CSP (`script-src 'self'`) silently blocks them — put pre-paint code in `public/` (e.g. `public/theme-boot.js`) and reference it with `<script src>`
- `dist/` is the loadable extension — do not reference `public/manifest.json` paths directly when reasoning about the running extension
- Content script and service worker must be IIFE — they cannot use `import` at runtime
- `Readability` is imported from `@mozilla/readability` npm package, not a local file
- `proxy/` is a standalone Node.js server for the podcast feature (separate `package.json`). Binds to `127.0.0.1:3456` only (`HOST`/`PORT` env override) and rejects browser requests whose `Origin` is not `chrome-extension://…` (extra origins via `PROXY_ALLOWED_ORIGINS`); the SW calls it at `http://127.0.0.1:3456`
- **Settings export**: `options/fields.ts` `SECRET_FIELDS` (= `platform/settings.ts` `SECRET_KEYS`) are left out of exports unless the user ticks "include secrets", and an import never clears a secret the file lacks
- Theme CSS uses compound selectors: `[data-theme-name="ocean"][data-theme="dark"]`
- **Popup visibility is state-driven**: popups/sheets/modals render conditionally from `stores/ui-store.ts` — there is no `.hidden` class toggling (the old trap of a JS-toggled `hidden` with a missing CSS rule is structurally gone). If you do add a class-toggled element, it needs its own CSS rule — jsdom logic tests can't catch a visually-unclosable popup
- TTS SSE events: `352`=audio chunk, `152`=session finish (may appear twice), `153`=failure — the SW (`sw-tts.ts`) translates them to simple `{type:'chunk'|'done'|'error'}` port messages
- **Stop button**: while streaming, the send button becomes Stop; `abortGeneration(tabId)` in `panel/lib/stream-controller.ts` disconnects the port AND finalizes directly — a port's own `onDisconnect` never fires for a `disconnect()` it initiated (only the SW end sees it; the SW keys its fetch abort off that). Every end of a stream (done / error / stop / SW gone) goes through the one idempotent `finalize()`
- **Background streams**: switching tabs never clears the outgoing tab's `isGenerating` (write it only via the core's `setGeneratingForTab`). The live answer lives in `stores/stream-store.ts` keyed by tab id — rendering is derived, so there is no re-attach machinery; an outcome that lands while its tab is hidden is simply there on return. Restored session state never restores in-flight flags (`isGenerating` / `isPodcastGenerating`)
- **TTS is window-global** ("printer resource"): nothing stops playback except the user (indicator chip) or the audio resource being claimed — a new playback (player's takeover point inside `initTTSPlayback`) or a podcast start (via `lib/audio-resource.ts`). Button state derives from `stores/tts-store.ts` (origin tabId+msgId), so tab switches / re-renders can never lose it. A plain send with autoplay off does NOT stop TTS
- **TTS synthesis is pipelined** (`panel/lib/tts/engine.ts`, shared by player and download paths): up to 2 concurrent segment requests, completed segments delivered strictly in order (one complete mp3 each; empty ones skipped), 30s-lookahead backpressure, retry-once per segment (always safe — nothing is delivered before a segment completes). A segment failing after retry degrades gracefully in the player: already-scheduled audio plays out instead of being killed mid-word. Segmentation is ONE deterministic greedy prefix rule (`panel/lib/tts/utils.ts` `nextCutEnd`): the streaming (autoplay) and batch (button/download) paths MUST produce identical cuts, because cache keys are per segment
- **TTS playback is a WebAudio sink, NOT MediaSource** (`panel/lib/tts/player.ts`): each segment's mp3 is decoded independently (`decodeAudioData`) and scheduled sample-accurately back-to-back with `AudioBufferSourceNode`s. Concatenating separately-encoded mp3s into one MSE timeline made Chrome repair the timeline under the playhead when a later file arrived — the recurring first-play "jump to the next segment" bug; cushion/sequence-mode mitigations only masked it. Every source MUST `connect(ctx.destination)` — an unconnected node is silent while `onended` still fires (mock tests can't catch physical wiring; asserted in `tests/panel/tts-player.test.js`). Segments are pushed into the schedule queue as **placeholders in delivery order before the first await** (`receiveSegment`) and filled in when their concurrent `decodeAudioData` completes — decode completion order may differ from delivery order (a longer segment decodes slower), and `pumpSchedule` never advances past an undecoded entry, so playback order always matches the text; a failed decode marks the entry dead so it skips without blocking the queue. Rate changes stop live sources and reschedule the unplayed remainder mid-buffer; `maybeFinished` needs `_decoding === 0` (a pending decode with empty sources is NOT "finished"); same-rate `setTTSPlaybackRate` is a no-op (a redundant call would audibly restart sources)
- **TTS audio cache** (`shared/tts-cache.ts`, IndexedDB store `ttsAudio`, db v4): key = sha-256(resourceId|speaker|format|sampleRate|segment text); value = the segment's complete mp3 Blob; LRU-evicted at 150MB (`_meta__` record keeps the byte total). Play / autoplay / download all share it — replays and download-then-play are free and instant. The options page shows usage and can clear it. Voice defaults live in `shared/tts-params.ts` (used by both the SW and the panel-side key builder)
- **Page cache vs navigation**: `TabState.pageUrl` records where `pageContent` was extracted; `state.invalidatePageIfNavigated` (wired to `chrome.tabs.onUpdated`) drops the cache when the tab moves to another URL (hash ignored) and notifies `pageInvalidated`
- **Talking to the content script**: use `sendToContentScript()` (`platform/messaging.ts`) — it injects `content.js` and retries when the tab has none (tabs opened before install/update). A failure means the page can't host one (chrome://, Web Store) → show `error.pageUnsupported`
- **Annotation state is per tab**: `panel/lib/annotation.ts` keys state by `sender.tab.id` in `stores/annotation-store` and the chip renders the active tab's state
- **Rendering model output**: all Markdown → DOM goes through `shared/markdown.ts` (`renderMarkdown` / `sanitizeHtml`: marked + DOMPurify), rendered by `panel/components/chat/MarkdownView.tsx`. Never `marked.parse` → `innerHTML` directly — answers are untrusted (the page is in the prompt). Remote images become links (never fetched), links get `target=_blank rel=noopener noreferrer`, non-http(s)/mailto hrefs are dropped. Inspect untrusted HTML with `parseInertHtml()` (a `<template>`), not a detached `div` — a detached div in the live document still fetches `<img>` sources. Chat history stores assistant **Markdown** (`format: 'md'`), not rendered HTML
- **Message ids**: every `ChatMessage` has an `id` (`shared/ids.ts` `genId`; legacy persisted messages get one on restore via `ensureMessageIds`). Retry / edit truncate history with `truncateHistoryFromId` — content matching (`truncateHistoryFromUserContent`) is only the fallback for id-less legacy bubbles, since it picks the wrong turn when two messages share text
- **User message meta**: user `ChatMessage`s carry `meta` (`rawText` / `displayText` / `quote` / `tabs`) next to the assembled API `content`; `UserBubble` renders from it for live sends, tab switches and history loads alike (so retry / edit keep working). `toApiMessage()` strips local fields (`meta`, `hadImages`, `type`) before anything goes to the model
- **IME-safe Enter**: keydown handlers that send on Enter must guard `e.nativeEvent.isComposing || e.keyCode === 229` (IME composition, see `Composer.tsx`) — otherwise Chinese/Japanese input sends mid-composition
- **Layering guardrail**: dependency-cruiser (`.dependency-cruiser.cjs`), not ESLint — see Source Layout. ESLint lints `.ts` through typescript-eslint (syntax-level `recommended` rules; `@typescript-eslint/no-unused-vars` is an error, `_`-prefixed args exempt)
- **Source maps**: inline only in dev/watch builds; `npm run build` ships none (keeps `dist/` ~4x smaller)
- **Image intake**: pending images live in `stores/composer-store.ts` (upload / paste / drag-drop / page-capture all funnel into `addImages`, FileReader part in `panel/lib/images.ts`). The chat model is assumed multimodal: images are always sent as `image_url` parts — there is no OCR fallback and no vision toggle (GLM-OCR and `visionEnabled` were removed; the options page clears the stale keys on save).
- **Sending**: every entry point that sends to the model goes through `submit()` / `panel/lib/send.ts` — never read the composer store piecemeal. A non-empty draft rides along with quick actions / quick commands as extra instructions (`draft.supplement` prompt); suggestion chips only fill the input.
- **History operations**: use `panel/lib/history-ops.ts` (`appendMessage`/`rollbackTrailingUserMessage`/`truncateHistoryFromId`) instead of mutating `tabState.conversationHistory` directly — it centralizes persistence + rollback policy.
- **State persistence**: `panel/state.ts` field setters persist to `chrome.storage.session` debounced (250ms); conversation helpers + `persistForTab()` flush immediately, and `switchToTab()` flushes the outgoing tab. Add new TabState fields as explicit getter/setter pairs.
- **SW chat streaming**: every non-agent chat call goes through `background/chat-runner.ts` (`streamToPort` for ports, `completeChat` for one-shot JSON calls) → a provider in `background/providers/` (`openai.ts` = OpenAI-compatible SSE via `shared/sse.ts`; `anthropic.ts` = native Messages API via `@anthropic-ai/sdk`, adaptive thinking). `settings.provider` picks it. The runner owns the idle watchdog (`IDLE_TIMEOUT_MS`), `finishReason` and usage accounting (`background/usage.ts` → `storage.local`, F9). **Automatic retry** (`MAX_ATTEMPTS = 2`): when a chat stream fails before any answer TEXT was produced — a connection drop or an API stream error, i.e. anything without an HTTP status — the runner posts `{type:'retry'}` and sends the same request once more instead of surfacing an error; the panel resets the live entry (`stream-store` `restart`: reasoning, text and search events of the dead attempt are void) and shows a toast. Never retried: after text started, an HTTP status (the request itself was refused), the idle watchdog, or a closed port. Reason: long HTTP/2 SSE streams to the API drop mid-body intermittently on some networks — measured 2026-11-23 on the test machine, a plain streaming fetch of one web-search answer broke in 6 of 16 runs, and web search makes streams 3–10× longer than a plain answer.
- **Agent mode (F11, opt-in `agentMode`)**: the tool loop runs on the **Vercel AI SDK** (`ai` v7, pinned exact) in `background/agent-runner.ts` — `streamText` + `stopWhen: isStepCount(AGENT_MAX_STEPS=6)`; `sw-openai.ts` routes `purpose:'agent'` there, everything else stays on chat-runner's hand-rolled providers (staged migration; batch callers are untouched). Tools are still declared and executed in the **panel** (`panel/lib/agent-tools.ts`, read-only: search / read paragraphs, selection, open tabs, highlight) because they need TabState (paragraphs, selection). Wire: per-call `agent_round` / `tool_call` messages down the port, one `tool_result` per call back up — the SDK executes a round's calls in parallel and keys results by toolCallId. Gotchas baked into agent-runner: system prompts must go through `instructions` (v7 rejects system entries in `messages`); `toModelMessages()` converts our persisted history (assistant `tool_calls` → `{type:'tool-call'}` parts, consecutive `role:'tool'` merged per round, image parts → `{type:'image'}`) and trims tool results older than the last 2 rounds to 500 chars; the `tool_call` message is posted from the fullStream consumer before `execute` registers, so an early-result buffer covers the race; `execute` never throws — a tool that never answers resolves to an explanatory string after `TOOL_RESULTS_TIMEOUT_MS`; hitting the step cap maps to `finishReason:'length'` + `limit:'steps'` (the panel words the note); the idle watchdog defers while tools are pending. Mock wire shapes for tests (MockLanguageModelV4): tool-call `input` is a JSON **string**, usage is nested (`{inputTokens:{total}}`), finishReason is `{unified, raw}` — see `tests/background/agent-runner.test.ts`. The AI SDK + zod add ~640KB to the IIFE `background.js` (~256KB → ~895KB); if that ever matters, switch the SW to `"type":"module"` + code splitting.
- **Web search (F15, default on `webSearch`; design + live measurements in `docs/design/设计方案_F15_联网搜索.md`)**: DeepSeek's **server-side** `deepseek_web_search` tool — the extension declares it and displays what comes back, it never searches itself. Declaring is NOT searching: the model decides per question (measured live 2026-11-23 on `deepseek-flash`: 0/5 article questions searched, 5/5 recency questions did, 5–11 s per searched answer, ~1,070 extra input tokens per request), which is why the setting defaults to ON — search is the norm, and the 🌐 button between the input and the send button (`WebSearchButton`, mirrors the options-page checkbox) is the opt-out. Three things travel together and are decided in the **worker**, because only it knows the tool will be declared: the `tools` entry (`providers/openai.ts` `withWebSearch()`), the rule (`prompts.ts` `websearch.rule`, sent as its OWN system message after the leading system messages — folded into `default` it would sit under the article), and a `latest_reminder` message (`shared/latest-reminder.ts`: `YYYY-MM-DD,<weekday>,,Web,<language>`, local date, directly before the last user message or the API returns 400; without it the model cannot tell today's date). Chat mainline only — `streamToPort` callers, never `completeChat` (JSON mode is refused next to the tool). Wire: `server_tool_event` chunks carry no `delta`, so the provider yields `search_event` for ALL of them — that is what keeps the idle watchdog alive while the model searches; only `call_started` / `call_completed` are forwarded, and completions arrive OUT OF ORDER within a step (`stream-store` matches by `call.id`). The complete `server_tool_calls` + `annotations` ride once on the `finish_reason` chunk → `finish.web` → `done.web` → `ChatMessage.web`. Citations are Unicode CODE-POINT offsets into the Markdown (the text itself has no markers): `shared/web-search.ts` `insertCitationMarkers()` inserts private-use `\uE000<n>\uE001` markers at RENDER time only and `MarkdownView` swaps them for numbered source links — `content` stays clean, so copy / TTS / share / export are untouched; markers are placed after the cited span, nudged out of a `**` run or a link destination (E-07) and, because the API ends a cited span BEFORE its sentence punctuation (every citation of the captured stream does), after that punctuation too — `…API”。[1] 在这之后`, never across a decimal point or an abbreviation (`3.14`, `e.g.`). `usage.server_tool_use.tool_search` counts QUERIES, not calls — count calls for display. `web` is local-only like `agentTrace` (`toApiMessage` strips it); a content-only history is accepted next to the tool (verified over 3 turns). Source URLs come from the API response and become `href`s only via `safeHttpUrl()`. No capability probing or downgrade for other endpoints/models: this build targets `deepseek-flash` (`deepseek-v4-pro` returns 400 "Please use deepseek-flash instead", shown on the error card as-is). Thinking params are untouched — thinking on (the model default) is "deep thinking search" (multi-step, opens pages), off is plain search; on measured better at an acceptable 5–11 s, so there is no fast mode. Agent mode (F11) and web search never share a request: with search on, `send.ts` sends plain chat (`agent: agentMode && !webSearch`) — a product choice (agent mode is on its way out), not an API limit; the API accepts both tool kinds together.
- **Chat history** lives in IndexedDB `chats` (`shared/chats-db.ts`), not `storage.local`. Chat ids are `chat_<ms>_<random>` — a bare timestamp collided for two saves in one millisecond
- **Page context (F1/F2)**: extraction returns paragraphs (`content/paragraphs.ts`) stored as `TabState.pageParagraphs`; `shared/context-builder.ts` labels them `[#N]` and, over the character budget, keeps the opening paragraphs + BM25-best matches for the question (no more tail truncation). Answers' `[#N]` become citation chips (`MarkdownView` post-processing → `panel/lib/citations.ts`): scroll + flash in the page, seek on YouTube, quote toast on PDFs
- **PDF / YouTube (F3)**: PDF tabs can't host a content script — `panel/lib/page-extractor.ts` `readTab()` routes `.pdf` URLs (or a `HEAD` saying `application/pdf`) to `panel/lib/pdf-extractor.ts`, which fetches the file and parses it with pdf.js, **lazy-loaded** (`pdf-loader.ts`; pdf.js + worker are separate chunks, never in the main bundle). On YouTube the content script returns the caption track as `[m:ss]`-stamped paragraphs (`content/youtube.ts`, parsing in `shared/youtube.ts`), falling back to Readability when a video has no captions
- **Highlights (F6)** are painted with the CSS Custom Highlight API (`content/highlights.ts`) — no wrapper elements in the page; anchoring is a text-quote selector (`shared/highlights.ts`). Deep-annotation results are cached per normalized URL + text hash (`annotations` store)
- **Context menu / shortcuts (F8)**: `background/sw-menus.ts` calls `sidePanel.open` first (must stay inside the user gesture), then queues the action in `storage.session` + messages an open panel; `panel/lib/panel-actions.ts` runs each action id once (TTL-guarded, tab-checked). Menu labels are inline zh/en (the SW cannot import `i18n.js`) — `sw-menus.ts` is on the prompt guard's CJK allowlist
- **Branches (F10)**: retry / edit keep the old continuation in `TabState.branches` (`panel/lib/history-ops.ts` `branchFromId` / `switchBranch`); never drop history tails directly
- **Podcast direct mode (F13, opt-in `podcastDirect`)**: `background/podcast-direct.ts` opens the Volcengine WebSocket from the worker; a `declarativeNetRequest` **session rule** (id 4201, that URL only, `tabIds: [-1]`) injects the X-Api-* headers and is removed after the session. Failure before any audio → falls back to the proxy. Frames: `shared/podcast-frames.ts`, pinned byte-for-byte to `proxy/server.js` by `tests/proxy/frames-compat.test.js` — change both together
- **Share image (F14)**: every finished answer carries a share button (`AnswerActions`); `panels/ShareModal.tsx` collects the markdown source, the nearest preceding user question and `pageTitle`, then `panel/lib/share-card.ts` builds a self-contained light card — inline `<style>`, theme `--primary` as the only accent, fixed light background in any theme. E-01 overflow cascade: paragraph-boundary cut at ~12k chars → rebuild at 560px → hard cut, with a `share.truncated` footnote. `panel/lib/share-image.ts` rasterizes via SVG `foreignObject` → canvas at 2x (1440px PNG; jsdom can't run this — logic tests cover card construction only). Two Chromium traps here, both found the hard way on a real machine: (1) an SVG containing `foreignObject` loaded from a **blob: URL always taints the canvas** (even bare text inside) — `toBlob` throws SecurityError; the identical SVG fed as a **data: URL** (`encodeURIComponent`) exports cleanly, so never switch back to `createObjectURL`; (2) `measureOffscreen`'s off-screen positioning (`position:fixed; left:-9999px`) must be stripped from the node after measuring — the same node is serialized right after, and the leftover style renders a nearly blank PNG. Downloads are named `小梨子_日期_标题前30字.png` via `sanitizeFilename` (`shared/download.ts`). Clipboard writes need the `clipboardWrite` manifest permission. The modal mounts the legacy-built card node into a React container (`replaceChildren`).
